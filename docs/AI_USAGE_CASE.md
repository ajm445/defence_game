# AI 활용 프로젝트 사례 — 막아라! 무너트려라!

> "코드를 잘 쓰는 개발자보다, AI 도구로 빠르게 만들어 실제 문제를 해결하는 빌더"
> — 채용 공고 中

이 문서는 위 인재상에 부합하는 **단일 프로젝트 사례 1건**입니다.
**Claude Code (Opus 4.6 / 1M 컨텍스트)** 를 페어 프로그래머로 활용해, 1인이 65일 만에 풀스택 실시간 멀티플레이어 웹 게임을 빌드한 과정과 워크플로우를 기록합니다.

---

## 1. 한 줄 결론

**Claude Code 를 "빠른 손"이 아닌 "장기 컨텍스트를 공유하는 동료"로 운영해, 1인이 65일·423커밋·73,000줄 규모의 운영 가능한 멀티플레이어 게임 서비스를 출시 수준까지 빌드했습니다.**

## 3. 핵심 워크플로우 — "AI 페어 프로그래밍 루프"

```
       [본인]                                  [Claude Code]
         │                                          │
   ① 문제/요구 정의 ──────────────────────▶  컨텍스트 흡수
         │                                          │
         │                                  ② 영향 범위 탐색
         │                                  (Glob/Grep/Read)
         │                                          │
   ③ 설계 토론 ◀──────────────────────  대안 제시 + 트레이드오프
         │                                          │
   ④ 결정 (본인이 주체)                            │
         │                                          │
         └──────────────────────────────▶  ⑤ 패치 작성
                                                    │
   ⑥ 인게임 플레이 테스트 ◀────────────  diff 확인
         │
   ⑦ 회귀 발견 시 → ① 로 (작은 사이클)
         │
   ⑧ 통과 → 의도 단위 git commit
         │
   ⑨ 매 마일스톤마다 CHANGELOG.md / MEMORY.md 업데이트
         │
         └──────▶  다음 세션의 컨텍스트가 됨 (장기 기억)
```

### 이 루프에서 "사람이 절대 위임하지 않은 것"
1. **무엇을 만들지** (제품 결정)
2. **언제 멈출지** (스코프 컨트롤)
3. **검증** (직접 플레이해서 체감)
4. **커밋 단위** (의도 단위로 분리)

### "사람이 적극적으로 위임한 것"
1. 초안 코드 생성, 보일러플레이트, 타입 정의
2. 영향 범위 탐색 (수십~수백 파일 grep)
3. 리팩터링 (예: `JSON.stringify` 캐싱, `.filter()` → 인플레이스 변경)
4. 트러블슈팅 첫 가설 5개 생성
5. 문서화 (CHANGELOG, MEMORY, 본 포트폴리오)

## 4. AI 와의 장기 컨텍스트 관리 — "MEMORY.md 시스템"

대화가 휘발성이라는 LLM 의 한계를 극복하기 위해, **프로젝트 루트에 컨텍스트 파일들을 두고 매 세션마다 자동 로드**되게 했습니다.

```
C:\Users\user\.claude\projects\D--defence-game\memory\
├── MEMORY.md                  ← 자동 로드 (인덱스, 200줄 제한)
├── server-optimization.md     ← V1.22.2 핫패스 최적화 상세
├── balance-history.md         ← 난이도 밸런스 히스토리
├── touch-ui.md                ← 모바일 터치 UI 스타일링
└── ...
```

`MEMORY.md` 안에는 다음과 같은 **재발 방지용 도메인 지식**을 누적합니다:
- 파일 매핑 표 (클라 ↔ 서버)
- 전직 스킬 쿨다운 표 (서버-클라 동기화 필수)
- 자주 발생하는 버그 패턴 10가지와 해결책
- 적응형 보간 튜닝 값
- 모바일 viewport 트릭 주의사항

**효과**:
- 새 세션에서도 AI 가 같은 실수를 반복하지 않음
- "왜 이렇게 짰지?" 라는 결정 기록이 남아, 미래의 본인에게도 도움
- 설명 비용이 매번 0에서 시작하지 않음 → 사이클 시간 단축

이건 단순한 노트 정리가 아니라 **AI 협업을 1인 개발의 실용 전략으로 만든 핵심 인프라**입니다.

## 5. 실제 사례 5선 — AI 가 실제로 풀어준 문제들

### 사례 1. 적응형 보간 시스템 설계 (가장 어려웠던 문제)
**상황**: 4인 멀티플레이에서 캐릭터가 끊겨 보이고, 핑이 흔들리면 경련처럼 보임. 고정 보간 상수로는 해결 안 됨.

**AI 활용**:
- Claude 와 **30분간 설계 토론**: "EMA 로 측정 vs 매번 계산 vs 고정 상수" 트레이드오프 비교
- 결론: EMA 기반 적응형 + 상태별(이동/정지/시전/스턴) 분기 로직
- AI 가 1차 구현 → 본인이 인게임에서 직접 핑 변동시켜 검증 → 수치 튜닝
- 결과 코드: `src/stores/useRPGStore.ts` 의 `applySerializedState` (~100줄)

**왜 AI 없이 못했나**: 1인 개발에서 이 정도 깊이의 설계 토론을 같이 할 사람이 없습니다. AI 가 실시간으로 대안을 던져준 게 결정적이었습니다.

---

### 사례 2. 서버 핫패스 최적화 (V1.22.2)
**상황**: 4인 협동에서 적·이펙트가 수백 개일 때 60fps 틱이 흔들림.

**AI 활용**:
- Claude 에게 "60fps 게임 루프 핫패스에서 흔한 비효율 패턴 10개 알려달라" 요청
- 받은 가설을 본인이 우선순위화: "GC 압력 → JSON.stringify 중복 → 거리 sqrt → find() 반복"
- AI 가 영향 범위를 grep → 약 20개 파일에 걸친 변경을 한 번에 작성
- 본인은 의미 단위로 4개 커밋으로 분리

**결과**:
- `hero.skills.find()` → `_skillQ/W/E` 캐시
- `Date.now()` → 틱당 1회 캐시
- `Math.sqrt()` → `distanceSquared()`
- `JSON.stringify` 1회 → `sendPreStringifiedMessage()`
- `.filter()` → 역순 `for + splice` 인플레이스
- `Array.shift()` O(n) → 인덱스 순회

**핵심**: AI 가 만든 패치를 통째로 받지 않고, **사람이 의미 단위로 쪼개 검증**한 게 안정성을 지킨 비결입니다.

---

### 사례 3. CSS zoom Safari 버그 — 트러블슈팅
**상황**: 모바일 스케일링을 CSS `zoom`으로 했더니, **Safari 에서만 화면 하단이 잘림**. iOS 에서 재현되는 골치 아픈 버그.

**AI 활용**:
- Claude 에게 증상 그대로 설명 + Safari + zoom + overflow 키워드로 가설 생성 요청
- 첫 가설: `overflow:hidden` + `zoom` 조합 시 Safari 의 layout viewport 계산 버그
- 대안 5개 비교: CSS transform scale / zoom / viewport meta 변경 / vw 단위 / SVG viewBox
- 결론: **viewport meta `width=1280` 동적 변경** 방식이 가장 단순하고 안정적
- 추가 발견: 전체화면 진입 시 viewport meta 가 초기화되는 이슈 → 150ms + 500ms 리트라이로 안정화

**결과**: CSS 분기 한 줄 없이 데스크톱 UI 한 벌만으로 모든 디바이스 대응. **`MEMORY.md`에 "CSS zoom 사용 금지" 항목으로 영구 기록**.

---

### 사례 4. 보안 강화 일괄 적용 (V1.26.8)
**상황**: 초기엔 게임에 집중하느라 보안이 허술. 랭킹 조작·XSS·세션 탈취 위험 발견.

**AI 활용**:
- Claude 에게 OWASP Top 10 기준으로 현재 코드 감사 요청
- 발견: REST API 인증 부재 / DM 채팅 XSS 가능 / 랭킹 검증 부족 / WebSocket 레이트 리밋 누락
- AI 가 일괄 패치 작성:
  - `requireAuth + requireSameUser` 미들웨어 신규
  - `sanitizeText()` 유틸로 채팅·DM 적용
  - heroClass / advancedClass / difficulty enum 화이트리스트
  - clearTime 최소 60초 검증
- 본인이 35개 파일 변경을 한 커밋으로 묶어 v1.26.8 로 릴리즈

**왜 의미있는가**: "1인이 보안까지 책임지는" 시나리오에서, AI 가 OWASP 체크리스트 역할을 해줘 빠뜨리는 항목 없이 일괄 강화가 가능했습니다.

### 사례 5. 캐릭터 스프라이트 파이프라인 (이미지 AI + 코드 자동화)
**상황**: 1인 개발이라 디자이너가 없음. 12 클래스 × 여러 모션 × 좌우 방향이 필요.

**AI 활용 (멀티 AI 파이프라인)**:
1. **Claude 와 함께 스프라이트 프롬프트 표준화** — 방향·자세·해상도 일관성을 위한 프롬프트 템플릿 작성
2. 이미지 AI 로 LEFT 방향 프레임 생성
3. **Claude 가 작성한 자동화 스크립트** (`scripts/combine-sprites.cjs`) 로 프레임 시트 합성
4. **`flip-frames.cjs`** 로 LEFT → RIGHT 자동 좌우 반전
5. 클라이언트 렌더러에 모션-스킬 싱크 시스템 추가 (V1.26.0~V1.26.6)

**결과**: 디자이너 없이도 12 클래스 × 다중 모션의 일관성 있는 스프라이트 시스템 구축. **AI 도구를 단일 사용이 아닌 파이프라인으로 엮은** 사례입니다.

## 6. AI 에게 위임하지 않은 것 — "사람이 지킨 영역"

| 영역 | 이유 |
|------|------|
| **제품 결정** | 어떤 기능을 넣을지, 빼야 할지는 본인이 사용자 입장에서 판단 |
| **검증** | 모든 패치는 본인이 직접 인게임에서 플레이하며 확인 |
| **밸런스** | 공식이 아닌 "재미"는 직접 플레이로만 알 수 있음 |
| **커밋 단위** | 의도 단위로 쪼개야 미래에 git log 가 의미를 가짐 |
| **릴리즈 결정** | 라이브 사용자에 영향이 가는 배포는 본인이 책임 |

이 경계를 분명히 한 게, AI 가 만든 결과물에 책임감을 가지고 운영할 수 있게 한 핵심입니다.

## 8. 회고 — 빌더 마인드로 배운 3가지

1. **AI 의 진짜 가치는 "타이핑 대체"가 아니라 "병목 제거"다.**
   - 코드를 빠르게 짜는 게 아니라, 막히는 시간을 없애는 도구로 써야 함.
   - Claude 가 빠를수록 본인의 시간이 *설계·검증·트레이드오프*에 더 쓰이게 됨.

2. **컨텍스트가 곧 생산성이다.**
   - LLM 은 매번 0에서 시작하면 매번 같은 실수를 반복함.
   - `MEMORY.md` 같은 장기 컨텍스트 인프라가 진짜 ROI 를 만든다.

3. **빌더 마인드 = 완벽한 코드보다 "지금 동작하는 것"을 우선.**
   - 423커밋 / 65일 = 매일 빌드 가능한 상태 유지.
   - 큰 PR 한 방이 아니라, 작은 사이클의 누적이 운영 가능한 서비스를 만든다.
